# 交付说明与复现指南

**项目**：基于树莓派 4B 与 STM32G431 的端侧多模态 AI 交互终端
**仓库**：https://github.com/Apple-1814/Design-and-Implementation-of-an-Edge-Side-Multimodal-AI-Interaction-Terminal-Based-on-Raspberry-Pi-4

## 2. 硬件

- 树莓派 4B Rev 1.5，8GB，Ubuntu 20.04.6 LTS（aarch64）。
- 蓝桥杯 CT117E-M4，STM32G431RBT6，板载 CMSIS-DAP。
- 官方 5V/3A（27W）USB-C 电源、短 USB 数据线、主动散热。
- 可选：5 寸 HDMI 屏、USB-TTL（VCP 异常时备用）。

## 4. llama.cpp 构建（Pi 4B，CMake 3.16 兼容）

当前 llama.cpp master 的内置 UI 资源脚本要求 CMake ≥3.18，Pi 4B（Ubuntu 20.04）为 3.16.3。**本项目不需要内置 UI**，采用无头构建：

```bash
cd ~/ai-terminal
curl -L -o llama.cpp.tar.gz https://github.com/ggml-org/llama.cpp/archive/refs/heads/master.tar.gz
tar -xzf llama.cpp.tar.gz && mv llama.cpp-master llama.cpp
cd llama.cpp

# 1) 关闭 UI：在 ui/apps/chat/CMakeLists.txt 顶部加入
#    if(NOT LLAMA_BUILD_UI)
#      return()
#    endif()
# 2) 注释 tools/server/CMakeLists.txt 中：
#    add_dependencies(${TARGET} llama-ui-assets)
#    target_link_libraries(... llama-ui ...) 中的 llama-ui
# 3) 新增 tools/server/ui.h 空实现（llama_ui_get_assets 返回空数组）
#    完整内容见本仓库 docs/llama_cpp_pi_build.md

cmake -S . -B build -DGGML_NATIVE=ON -DLLAMA_CURL=OFF \
  -DCMAKE_BUILD_TYPE=Release -DLLAMA_BUILD_UI=OFF
cmake --build build --target llama-server -j4
```

## 5. 启动

> 已配置 **systemd 开机自启**：`llama.service`、`vlm.service`、`ai-terminal.service`。正常演示只需给树莓派上电；开机约 **22 秒** API 上线，LCD 显示 `192.168.49.50` / `READY`。
>
> 首次安装自启：`ROOT=/home/apple/ai-terminal bash scripts/install_services.sh`。
>
> 课堂电脑/Pi 固定 IP 与手机共享网络见 `docs/课堂演示网络配置.md`。

```bash
# 手动启动（调试用；开机自启已覆盖）
ROOT=$HOME/ai-terminal bash scripts/start_all.sh

# 或分别启动
bash scripts/run_llama.sh
bash scripts/run_vlm.sh
cd pi && bash run.sh
```

浏览器访问 `http://<树莓派IP>:8000/`。设备状态应显示“串口已连接”。

知识库源目录为外部教程（默认 `D:\BaiduNetdiskDownload\蓝桥杯嵌入式教程完整版（去加密）`），**不随仓库提交**。

## 7. 固件烧录

```bash
# 树莓派，CMSIS-DAP + pyOCD
pyocd flash --pack ~/Keil.STM32G4xx_DFP.1.6.0.pack \
  -t STM32G431RBTx -f 100k firmware/release/command_firmware.hex
pyocd reset --pack ~/Keil.STM32G4xx_DFP.1.6.0.pack -t STM32G431RBTx
```

烧录后若 VCP 写阻塞，**物理拔插 USB 一次**；或在树莓派上重新枚举：

```bash
sudo sh -c 'echo 0 > /sys/bus/usb/devices/1-1.1/authorized; sleep 1; echo 1 > /sys/bus/usb/devices/1-1.1/authorized'
```

## 8. 演示流程（3 分钟）

1. 打开聊天页，问“CT117E-M4 怎么快速入门？” → 知识库直答，展示入门路线与来源。
2. 问“LED 怎么点亮？PC8–PC15 和 PD2 怎么配置？” → 板卡要点 + 本机固件代码；点击右侧 LED“开/关” → 自动切到“代码讲解”，顶部“本次操作代码”显示该灯的前后位图与 `LED_Disp()` 参数，下面是时钟→引脚→锁存→main 的完整代码，可复制。
3. 问“I2C 读写 AT24C02 怎么写？” → 板卡要点 + 官方 BSP 代码。
4. 输入“让 LED1 亮起来” → `OK LED 1 1`，LED1 点亮；再“关掉 LED1”。
5. 输入“在 LCD 上显示 Hello” → 清屏并显示；面板读取 ADC1(PB12)、ADC2(PB15)，显示原始值与电压。
6. 面板设置 PWM1(PA2)=20%、PWM2(PA3)=40%，应用后回读一致；示波器/万用表可测约 0.66V / 1.32V 平均电压。
7. 点击图片按钮上传图片，输入“请描述这张图片” → SmolVLM 回答。
8. 打开 `paper/课程设计报告.docx` 与 `paper/答辩PPT.pptx` 讲解架构与数据。

## 10. 已知限制

- 板载 VCP 仅 9600，且烧录/复位后可能写阻塞；高波特率需 USB-TTL。
- VCP 只接受单次持久会话；后端必须常开串口句柄。
- 1.5B 模型能力比 0.5B 明显提升，但仍小于云端大模型；开放问题约 40–120s，复杂推理有限。
- 引脚/事实/概念类问题走确定性直答，不受模型速度影响；课堂演示优先用这些快捷问题。
- 当前无摄像头，VLM 仅支持上传图片。
- 硬件命令采用规则路由优先，LLM 不直接操作硬件；后续可引入 GBNF/function calling。
- 知识库中 3 份真题 DOCX 与 422 页 OneNote PDF 主要是截图，未 OCR，只检索到目录/标题；旧平台（F103/STC15）内容已降权。
- 0.5B 开放问题回退约 20–60s；课堂演示优先用快捷问题/知识库直答。
- `paper/figures/ui-chat.png` 是**界面布局示意**，答辩前建议用实际浏览器截图替换；报告封面班级/组员/教师为占位，需要填写。
- Proteus 仿真未在本仓库内执行；报告中的 UART/PWM 图为协议/时序示意，实际以实测 ACK/回读为准。
