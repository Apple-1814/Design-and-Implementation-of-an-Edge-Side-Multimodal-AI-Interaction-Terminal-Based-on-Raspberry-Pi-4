## 一、概述与应用背景

### 1.1 设计背景

大语言模型（LLM）与视觉语言模型（VLM）通常依赖云端 GPU 推理，存在网络依赖、隐私暴露、延迟不可控等问题。随着量化推理与边缘计算的发展，在资源受限的嵌入式设备上本地运行小参数模型成为可能。本设计以树莓派 4B 为边缘计算平台，以 STM32G431 为实时控制单元，构建一个**离线可用的多模态 AI 交互终端**：

- 树莓派本地运行 Qwen2.5-0.5B-Instruct（LLM）与 SmolVLM-500M（VLM）；
- 浏览器提供类 DeepSeek 的聊天界面，支持流式输出、会话历史和图片上传；
- 通过 USB CDC 虚拟串口把自然语言转换为 STM32 命令，控制 LED、LCD、ADC、PWM；
- 可选通过 CMSIS-DAP + pyOCD 烧录预编译固件，演示脱机运行。

### 1.2 研究现状

- **端侧 LLM**：llama.cpp、GGUF 量化、Q4/Q8 低比特推理，使 0.5B–3B 模型可在 ARM CPU 上运行。
- **多模态**：SmolVLM、Qwen2-VL 等小参数 VLM 支持单图问答；llama.cpp 的 mtmd 模块支持 GGUF 多模态。
- **嵌入式 AI 终端**：MCU 负责实时外设控制，应用处理器负责推理与人机交互，形成异构边缘架构。
- **本设计的定位**：不追求模型规模，而强调“本地推理 + 硬件闭环 + 可复现工程”，适合课程设计与端侧应用原型。

### 1.3 设计目标

1. 树莓派本地完成 LLM 对话与 VLM 图片问答，不依赖云端 API。
2. Web 界面具备流式输出、会话管理、设备状态与硬件控制面板。
3. STM32 通过 UART 接收命令并执行 LED/LCD/ADC/PWM，返回 ACK。
4. 自然语言能够触发硬件动作，形成“语言 → 命令 → 执行 → 回读”闭环。
5. 完成课程报告、电路图、仿真、流程图与作品演示。

### 4.1 系统框图

```text
│ 浏览器（PC / 平板 / Pi 本机） │

│  ├─ llama.cpp：Qwen2.5-0.5B   │
│  ├─ SmolVLM-500M（M5）        │
│  ├─ 规则路由 / 脚本引擎        │
│  └─ 持久串口服务               │
└──────────────┬───────────────┘
               │ USB CDC（CMSIS-DAP VCP，9600 8N1）
┌──────────────▼───────────────┐
│ STM32G431（CT117E-M4）        │
│ LED / LCD / ADC / PWM / 按键  │
└──────────────────────────────┘
```

### 4.2 电源树

```text
220V → 官方 27W USB-C 电源 → 5V/3A
  ├─ 树莓派 4B（5V）
  ├─ 5 寸 HDMI 屏（5V，可选）
  └─ 开发板 USB（5V → 板载 3.3V LDO）
        └─ STM32G431 / LCD / LED / 电位器（3.3V）
```

### 4.3 引脚与接线

| 信号 | 树莓派 | STM32G431 | 说明 |
|---|---|---|---|
| USB D+/D− | USB-A | 板载 CMSIS-DAP | 烧录 + 虚拟串口 |
| UART TX | — | PA9（USART1_TX） | 板载 VCP 内部连接 |
| UART RX | — | PA10（USART1_RX） | 板载 VCP 内部连接 |
| LED | — | PC8–PC15 + PD2 锁存 | 8 位 LED |
| LCD | — | 板载并口 | 240×320 |
| ADC | — | PB12（ADC1_CH11） | 电位器 |
| PWM | — | PA2（TIM15_CH1） | 外部 LED/示波器测量 |
| 按键 | — | PA0/PB0/PB1/PB2 | 4 键 |

> 实物接线以开发板丝印与原理图为准；本课设不涉及自制 PCB。

### 4.4 仿真方案与结果

- **仿真工具**：Proteus / 立创EDA（MCU 子系统与关键电路）。
- **可仿真项**：UART 帧时序、PWM 占空比、ADC 采样、按键消抖、LED 限流。
- **不可仿真项**：树莓派、Linux、llama.cpp、LLM/VLM、摄像头、Web 前端、ST-Link/CMSIS-DAP 烧录。
- **实测替代**：UART 命令往返 <200ms；PWM 寄存器回读 0/50/100%；ADC 读回 1759（12 位原始值）；LCD 清屏后仅显示 `Hello`。
- **结论**：MCU 侧逻辑通过仿真/实测验证；Pi/LLM 侧以实机运行为准，报告中明确边界，不将“仿真通过”写成“系统通过”。

### 4.5 关键电路说明

- **USB 供电与保护**：Pi 使用官方 5V/3A 电源；开发板由 USB 供电，避免同时反灌。
- **UART 电平**：USART1 为 3.3V；TX 配置为 `GPIO_MODE_AF_PP`（推挽），禁用开漏 `AF_OD`。
- **ADC**：PB12 电位器分压，ADC1_CH11，12 位、640.5 周期采样。
- **PWM**：TIM15_CH1（PA2），80MHz/(79+1)=1MHz，Period=999 → 1kHz；占空比 0–100% 对应比较值 0–1000。
- **LED**：PC8–PC15 经 74HC573 锁存，PD2 为锁存使能。

## 五、程序流程图

### 5.1 系统主流程

```text
上电
  → 初始化 LCD / LED / 按键 / ADC / PWM / USART1
  → 发送 READY
  → 主循环
       ├─ 从环形缓冲取字节
       ├─ 按行解析命令
       ├─ 执行 LED / LCD / ADC / PWM
       └─ 返回 OK / ERR
```

### 5.2 命令解析流程

```text
串口中断 → CMD_FeedByte() → 环形缓冲
主循环 CMD_Proc()
  → 拼行（\n 结束）
  → PING / LED / LEDALL / LCD / LCDCLR / ADC? / PWM / PWM?
  → 参数校验
  → 执行 BSP
  → 发送 ACK
```

### 5.3 LLM 对话与硬件路由

```text
用户输入
  → POST /api/chat
  → tool_router 规则匹配
       ├─ 命中：执行串口命令 → 返回“已执行 … → OK …”
       └─ 未命中：转发 llama-server /v1/chat/completions（SSE）
  → 前端流式渲染
```

### 5.4 烧录流程

```text
PC Keil 编译 → .hex
  → SCP 到树莓派
  → pyOCD + Keil STM32G4 DFP
  → 备份当前 Flash → 烧录 → 校验 → 复位
  → 若 VCP 写阻塞：物理拔插 USB 重新枚举
```

## 七、设计方案中的不足及改进

1. **VCP 仅 9600**：板载 CMSIS-DAP 虚拟串口对 115200 线码设置会阻塞，命令链路保持 9600；高波特率需 USB-TTL。改进：外接 CH340/CP2102 或改用 Pi GPIO UART。
2. **VCP 单会话/烧录后阻塞**：频繁 open/close 会写阻塞，需物理拔插 USB 或重新枚举。改进：后端常开串口句柄；烧录后自动重连/提示用户重插。
3. **小模型能力有限**：0.5B 模型知识面与推理能力有限，复杂问题易出错。改进：1.5B/3B（需更高内存与更慢速度）、RAG 知识库、端云协同。
4. **VLM 速度与效果**：SmolVLM-500M 单图较慢，复杂 OCR/推理有限。改进：更强 VLM（Qwen2.5-VL-3B，需 GPU/NPU）、图片预处理、限制输出长度。
5. **无摄像头**：当前 VLM 仅支持上传图片。改进：增加 Camera Module 3 或 USB 摄像头，实现拍照问答。
6. **规则路由优先**：硬件指令用规则匹配以保证稳定，LLM 不直接控制硬件。改进：引入结构化 function calling / GBNF 约束，让 LLM 在受控白名单内选择工具。
7. **仿真边界**：Proteus 无法仿真 Pi/LLM/摄像头，报告只仿真 MCU 子系统。改进：补充实测波形与系统级测试，明确“仿真/实测”边界。
8. **供电敏感**：Pi 欠压会导致 VCP 重枚举与系统不稳定。改进：官方 27W 电源、短 USB 线、必要时带供电 Hub。

## 八、实验总结

本设计完成了从“自然语言”到“硬件动作”的端到端闭环：

- 在树莓派 4B 上完成本地 LLM 推理与 Web 交互；
- 在 STM32G431 上实现 LED/LCD/ADC/PWM 的 UART 命令协议；
- 通过 FastAPI 持久串口服务与规则路由，实现中文指令控制硬件；
- 完成 CMSIS-DAP 烧录、原固件备份、前端静态托管与验证记录；
- 30 分钟稳定性测试完成 180 轮、**933 次检查、0 失败**，最高温度 47.2°C。

课程设计过程中遇到并解决了若干工程问题：CMSIS-DAP 与 ST-Link 的差异、USART TX 开漏导致无法回读、VCP 单会话/115200 限制、烧录后欠压与 USB 重枚举、LCD 演示函数覆盖命令显示等。这些问题说明：**端侧 AI 项目的难点不仅在模型，更在供电、总线、时序与软硬件边界**。

后续可扩展：1.5B/3B 模型、VLM 摄像头、语音输入/播报、NPU 加速、端云对比、外壳与扩展板。通过本设计，组员掌握了嵌入式 Linux、STM32 HAL、串口协议、FastAPI、前端与边缘推理的联合调试方法。
